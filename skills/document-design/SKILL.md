# ドキュメントデザイン規約

ドキュメントを作るときの配色・書体・レイアウトを固定する。
**毎回デザインを考え直さない。** ここの規則と同梱の `reference.css` をそのまま使う。

プロジェクト固有のデザインシステム（CLAUDE.md、トークンファイル、既存コンポーネント）が
存在する場合は**そちらを優先する**。この規約はそれが無いときの既定値。

詳細は必要になったときに読む。

| 参照先 | 内容 |
|---|---|
| `references/html-implementation.md` | HTML 出力時の実装規約。マークアップの語彙・書体・カラートークン・レイアウト・React Aria 互換の命名・Artifact の制約・印刷 CSS |
| `reference.css` | スタイルの実体。`<style>` に丸ごと貼る |

## 適用手順

1. 出力先を確定する（Artifact / 単体 HTML / Markdown）
2. `date "+%Y-%m-%d %H:%M"` を実行して作成日時を得る。推測で書かない
3. 文章の規則に従って本文を書く
4. HTML 出力なら、この SKILL と同じディレクトリの `reference.css` を Read し、
   `<style>` に**丸ごと貼ってから**差分を足す。色・書体・印刷 CSS を自作しない
5. 追加スタイルは `reference.css` の `@media print` ブロックより**前**に置く
   （印刷 CSS は後勝ちで暗テーマを上書きする設計のため、最後に置く必要がある）

## 出力先ごとの扱い

| 出力先 | reference.css | mermaid | 備考 |
|---|---|---|---|
| Artifact | 貼る | `<pre class="mermaid">` でそのまま描画される | CSS/JS インライン必須。画像は data URI |
| 単体 HTML | 貼る | ライブラリ無しでは描画されない。SVG に描き出すか描画済みで埋め込む | |
| Markdown | 使わない | ` ```mermaid ` フェンス（GitHub 等のレンダラが描画） | 色に頼らず見出し・表・リストの構造だけで階層を作る |

文章の規則は出力先を問わず全てに適用する。

## 文章の規則

読み手は人間である。機械可読性や網羅性より、読んで理解できることを優先する。

### 文体

- **「だ・である」調で統一する。** 「です・ます」調と混在させない
- 冗長な言い回しを避ける。一文は短く切る
- 事実のみを書く。推測を書く場合は推測であると明示する
- 「〜と言えるでしょう」「〜かもしれません」のような曖昧な結びを使わない
- 修飾を重ねない（「非常に重要な」「極めて有用な」等）

### 強調

- **太字は必要な箇所のみ。** 1 節に 1〜2 箇所を上限の目安とする
- 強調が多い文章は、どこも強調されていない文章と同じである
- 斜体は日本語で判別しにくいため使わない
- 感嘆符を使わない

### 構造

認知負荷を下げることを目的に構造化する。装飾目的では使わない。

- **並列する情報は表にする。** 箇条書きの繰り返しより表のほうが比較しやすい
- 手順・分類・対応関係は図表に落とす
- 1 節が長くなったら小見出しで分ける
- 連番は中身が実際に順序を持つときだけ振る

### 動的な表現

**タブ・アコーディオン・表・図を積極的に使い、認知負荷を下げる。**
文章を上から下まで読ませるより、読み手が必要な箇所に辿り着けるようにする。

| 表現 | 使う場面 | 使わない場面 |
|---|---|---|
| 表 | 並列する項目の比較。新旧の対比 | 項目が 2 つ以下 |
| タブ | 同じ構造の内容を切り替える（出力先別、言語別、環境別） | 内容を並べて比較したい |
| アコーディオン | 補足・詳細・長いコード。既定は閉じる | 読み手が必ず読む必要がある内容 |
| 図（mermaid） | 依存関係・状態遷移・フロー | 文章 1 行で足りる関係 |

判断基準:

- **並べて比較したいならタブにしない。** タブは同時に見えない
- **アコーディオンに要点を入れない。** 閉じた状態で意味が通る資料にする
- 3 つ以上の選択肢が同じ構造ならタブにまとめる
- 縦に長い資料は、節が 5 つを超えたあたりで目次かタブを検討する

実装は `<details>` と radio ハックで組み、**JavaScript を使わない**。
外部ライブラリに依存せず、印刷対応も CSS だけで完結するため
（Artifact でもインライン JS 自体は動くが、使う理由がない）。
CSS は `reference.css` に含まれる。マークアップは後述の語彙に従う。

マークアップの実体は `references/html-implementation.md` にある。HTML を出力するときに読む。

### 新旧の比較

リアーキテクチャ・移行・仕様変更など**新旧が比較可能な内容では、必ず比較表を含める。**
文章で「〜が改善された」と書くだけでは差分が伝わらない。

| 観点 | 変更前 | 変更後 |
|---|---|---|
| （比較軸） | （現状の値・挙動） | （変更後の値・挙動） |

数値が比較できる場合は数値を入れる。定性的な差しかない場合はその旨を書く。

### 作成日時

**資料の右上に作成日時を時刻まで入れる。** 内容が時点依存であることを読み手に示すため。

```html
<div class="doc-meta">作成 2026-07-30 02:12</div>
```

- **書式は `YYYY-MM-DD HH:MM`。** 日付だけにしない
- 同日に複数版を作る資料では時刻が版の識別子になる
- **生成時点の日時をハードコードする。** スクリプトで動的に取得しない
  （資料の作成日時は固定値であり、閲覧日時ではない）
- スタイルは `reference.css` の `.doc-meta`（狭い画面での static 化も定義済み）
- Markdown 出力では右寄せができないため、冒頭に `作成: YYYY-MM-DD HH:MM` と 1 行置く

### 参考文献

- 本文中に URL を散らさない。**資料の末尾に「参考文献」節としてまとめる**
- 参照した資料は必ず挙げる。読み手が辿れない情報源は使わない
- 本文から参照する場合は節名で指す
- **リンクテキストは資料名にする。** URL をそのままテキストにすると、
  印刷 CSS の URL 併記と二重に出る

## 出力先が Markdown の場合

- 色・CSS を使わない。**見出しの階層、表、リスト、コードブロックだけで構造を作る**
- 強調は `**` のみ
- 表の桁揃えに頼らない（レンダラによって崩れる）
- 作成日時は右寄せできないため、冒頭に `作成: YYYY-MM-DD` と 1 行置く

## やらないこと

デザイン面:

- 配色・書体をその場で考え直す（`reference.css` を使う）
- グラデーション、絵文字の見出し記号、全要素の中央寄せ
- 意味のない装飾のアクセントバー
- `@media print` を省略する。印刷 CSS より後に追加スタイルを置く
- 動的表現を JavaScript で作る（`<details>` と radio ハックで足りる）
- アコーディオンに要点を隠す
- 比較したい内容をタブに分ける（同時に見えない）

文章面:

- 「です・ます」調との混在
- 太字の多用（強調が多い文章は強調が無い文章と同じである）
- 推測を事実として書く
- 並列情報を箇条書きの繰り返しで並べる（表にする）
- 新旧が比較できる内容で比較表を省く
- 本文中への URL の散らし書き（末尾にまとめる）
- リンクテキストを生 URL にする（印刷で二重に出る）
- 中身が連番でないのに `01 / 02 / 03` を振る
- 作成日時を日付だけにする（時刻まで入れる）
- lorem ipsum（必ず実際の内容で組む）
